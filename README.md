# Личный ассистент в Telegram

Бот умеет:
1. **Напоминания** — «напомни завтра в 12:00 обработать заказ»
2. **Запись заказов в Google Таблицу** — просто опиши заказ свободным текстом.
   Бот сам генерирует короткий номер заказа (например `A1042`) и присылает его в ответ —
   передай этот номер клиенту. **В одном заказе может быть сколько угодно товаров:**
   «@ivanov заказал кроссовки Nike 42 чёрные за 7500 и куртку Stone Island M за 12000».
   Дозаказать потом — «в заказ A1042 добавь ещё кепку New Era за 3000».
3. **Изменение статуса заказа** — «статус A1042 = 3» (число, см. таблицу ниже)
4. **Трекер заказов для клиентов** — отдельный Telegram-бот с Mini App **PR0JECT**.
   Клиент открывает приложение и видит **все свои заказы** автоматически (по @username из таблицы).
   Ты меняешь статус через ассистента: «статус A1042 = 3» — клиент сразу видит обновление
   в приложении **и получает пуш-уведомление** от клиентского бота.
5. **Смена статуса пачкой** — «все заказы со статусом 2 переведи в 3»,
   все клиенты получают уведомления разом
6. **Поиск заказов** — «что с A1042», «покажи заказы @ivanov»
7. **Учёт денег** — назови закупку и продажу в описании заказа,
   `/stats` и `/month` посчитают прибыль
8. **Зависшие заказы** — бот сам раз в день пишет, что стоит без движения
   дольше `STUCK_ORDER_DAYS` дней (по умолчанию 10), плюс команда `/stuck`
9. **Активные заказы** — `/active` или «сколько активных заказов»: сколько сейчас
   в работе и расклад по этапам (доставленные не считаются)
10. **Фото товаров** — пришли одно фото или сразу альбом с номером заказа в подписи.
   Фото копятся у заказа, клиент листает их галереей в приложении
11. **Переписка с клиентами** — сообщения из клиентского бота приходят в ассистент,
    ответ реплаем уходит клиенту
12. **Разбор конкурентов/рекламных каналов** — пришли ссылку на публичный канал (t.me/name)

Всё остальное (обычные вопросы) бот тоже понимает — отвечает как обычный ассистент.

### Этапы заказа (колонка "Статус" в таблице)
1. Товар выкуплен
2. Прибыл на склад в Китае
3. Едет Китай → Москва
4. Проходит таможенный досмотр
5. Прибыл в Москву
6. Передан в доставку
7. Доставлен

Список задаётся в `config.ORDER_STATUSES` — всё остальное (подсказки для Gemini,
эмодзи в уведомлениях, шаги в мини-приложении) подтягивается оттуда автоматически.
**Важно:** вставка нового этапа в середину сдвигает смысл всех номеров после него,
поэтому уже записанным заказам нужно поднять статус на единицу.

## Два бота

| Бот | Переменная | Для кого |
|-----|------------|----------|
| **Ассистент** | `TELEGRAM_BOT_TOKEN` | Тебе: заказы, статусы, напоминания, анализ каналов |
| **Клиентский** | `CLIENT_BOT_TOKEN` | Клиентам: Mini App «Мои заказы» + пуши о статусе |

При записи заказа через ассистента **обязательно указывай @username клиента** —
по нему Mini App находит все его заказы в таблице.

### Дизайн Mini App

Оформление трекера — премиальная тёмная тема по правилу 60/30/10:

| Роль | Цвет | Где используется |
|------|------|------------------|
| Основа (60%) | `#0E1E39` | фон приложения, панели, карточки |
| Акцент (30%) | `#D8B45A` | активный этап, прогресс, кнопки, чипы |
| Контраст (10%) | `#F6F4EF` | текст, отметка доставленного заказа |

Все оттенки выведены из этих трёх цветов через переменные в начале `webapp/style.css` —
менять тему нужно только там. Цвет шапки Telegram задаётся в `webapp/app.js` (`THEME_BG`),
он должен совпадать с основой, иначе появится шов между шапкой и приложением.

### Постоянное хранилище (Railway Volume)

Файловая система Railway очищается при каждом деплое, поэтому базы SQLite
(клиенты, напоминания, история диалога) лежат в папке из переменной `DATA_DIR`:

- локально — не задана, файлы создаются в корне проекта
- на Railway — примонтирован volume, `DATA_DIR=/data`

Если поднимаешь проект на новом хостинге: создай постоянный диск, примонтируй
его и укажи путь в `DATA_DIR`. Без этого клиентам придётся заново нажимать
`/start` после каждого обновления кода, а напоминания будут теряться.

### Пуш-уведомления клиенту

Telegram разрешает боту писать только тем, кто сам открыл с ним диалог, поэтому:

1. Клиент один раз нажимает `/start` в клиентском боте — его `@username` и `chat_id`
   сохраняются в `clients.sqlite` (файл создаётся автоматически)
2. Ты меняешь статус через ассистента: «статус A1042 = 3»
3. Клиентский бот присылает клиенту сообщение с новым этапом и кнопкой «Открыть трекер»

Ассистент в ответ пишет, ушло ли уведомление. Если клиент ещё не нажимал `/start`
в клиентском боте — статус в таблице всё равно обновится, но пуш не доставится,
и ассистент об этом предупредит.

## Шаг 1. Получить токены Telegram-ботов

1. Напиши в Telegram боту **@BotFather**
2. Создай **двух** ботов командой `/newbot`:
   - **Ассистент** — для себя (запись заказов, статусы, напоминания)
   - **Клиентский** — для клиентов (только Mini App с трекером)
3. Сохрани токены: `TELEGRAM_BOT_TOKEN` и `CLIENT_BOT_TOKEN`

## Шаг 2. Получить ключ Gemini API

1. Зайди на **aistudio.google.com/apikey**, войди с Google-аккаунтом
2. **Create API key**
3. Сохрани ключ — это `GEMINI_API_KEY`

## Шаг 3. Настроить доступ к Google Таблице

1. Зайди на **console.cloud.google.com**, создай новый проект (или используй существующий)
2. Включи **Google Sheets API** и **Google Drive API** (Библиотека API → найти → Включить)
3. Раздел **IAM и администрирование → Сервисные аккаунты → Создать сервисный аккаунт**
4. После создания — открой аккаунт → вкладка **Ключи** → **Добавить ключ → JSON**
5. Скачается файл — переименуй его в `credentials.json` и положи в корень проекта
6. Открой файл, скопируй значение `"client_email"` (выглядит как `xxx@xxx.iam.gserviceaccount.com`)
7. Открой свою Google Таблицу с листом **«Заказы»** → кнопка **«Настройки доступа»** →
   добавь этот email как **Редактора**
8. Скопируй **ID таблицы** — это часть ссылки между `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/ВОТ_ЭТО_ID/edit`

Колонки **«Номер заказа»** и **«Статус»** добавлять руками не нужно — бот сам допишет
заголовки в конец листа при первом обращении к таблице, если их там ещё нет.

**Одна строка листа = один товар.** Заказ из нескольких товаров — это несколько строк
с одним и тем же номером заказа: клиент, статус и дата смены статуса у них общие,
а при чтении они склеиваются в один заказ. Статус меняется сразу у всех строк заказа.

## Шаг 4. Настроить переменные окружения

Скопируй `.env.example` в `.env` и заполни все значения:

```bash
cp .env.example .env
```

`OWNER_CHAT_ID` пока можно оставить пустым — узнаешь его после первого запуска (бот покажет в ответ на `/start`).

## Шаг 5. Запустить локально (для проверки)

```bash
python -m venv venv
source venv/bin/activate  # на Windows: venv\Scripts\activate
pip install -r requirements.txt
python -m bot.main
```

Напиши боту `/start` в Telegram — если ответил, всё настроено верно.

Проверить подключение к таблице отдельно:
```bash
python -m bot.sheets_service
```
Если в таблице появилась тестовая строка — доступ настроен правильно.

Проверить трекер заказов локально (без бота, только API + Mini App статика):
```bash
uvicorn bot.api:app --reload --port 8080
```
Открой `http://127.0.0.1:8080/app/` в браузере — увидишь ту же страницу, что откроется
в Telegram (вне Telegram `Telegram.WebApp.CloudStorage` недоступен, список заказов
сохраняется в `localStorage` браузера как запасной вариант).

## Шаг 6. Задеплоить на Railway (чтобы бот работал 24/7)

1. Залей код в свой репозиторий на GitHub
2. Зайди на **railway.app**, войди через GitHub
3. **New Project → Deploy from GitHub repo** → выбери свой репозиторий
4. Во вкладке **Variables** добавь все переменные из своего `.env` (кроме `GOOGLE_CREDENTIALS_FILE` —
   вместо пути, для credentials.json есть два варианта см. ниже)
5. Railway сам определит `Procfile` и запустит бота (процесс `web`, слушает `$PORT`)
6. Открой вкладку **Settings → Networking → Generate Domain** — Railway выдаст публичный
   https-адрес вида `https://your-app.up.railway.app`, он проксируется на `$PORT`, который
   слушает встроенный API/Mini App сервер
7. Впиши в Variables `MINI_APP_URL=https://your-app.up.railway.app/app/` (со слэшем в конце)
   и `CLIENT_BOT_TOKEN` — после передеплоя в клиентском боте появится кнопка «📦 Мои заказы»

Регистрировать Mini App через @BotFather не нужно — кнопка `web_app` в обычной клавиатуре
работает с любой https-ссылкой без дополнительной настройки.

### Как передать credentials.json на Railway
Так как это чувствительный файл, а не текстовая переменная, есть два пути:
- **Проще:** добавить `credentials.json` в репозиторий (если репозиторий приватный) — тогда ничего менять не нужно
- **Безопаснее:** создать переменную `GOOGLE_CREDENTIALS_JSON` с полным содержимым файла в виде текста —
  `bot/config.py` уже умеет сохранять её в `credentials.json` при старте, если сам файл не задеплоен

## Структура проекта

```
tg-assistant/
├── bot/
│   ├── main.py              # ассистент + запуск API и клиентского бота
│   ├── client_bot.py        # клиентский бот: /start, Mini App, пуши о статусе
│   ├── clients_service.py   # клиенты, настройки, переписка (clients.sqlite)
│   ├── photo_service.py     # галерея фото заказа в постоянном хранилище
│   ├── telegram_auth.py     # проверка подписи Telegram WebApp initData
│   ├── api.py               # GET /api/my-orders, /api/status/{номер}, /api/photo/{номер}/{n}
│   ├── gemini_service.py    # общение с Gemini (распознавание намерений)
│   ├── sheets_service.py    # запись в Google Таблицу, номера/статусы заказов
│   ├── scheduler.py         # планировщик напоминаний
│   └── channel_analyzer.py  # загрузка постов публичных каналов
├── webapp/                  # Telegram Mini App (трекер заказов для клиентов)
│   ├── index.html
│   ├── style.css
│   ├── logo.png             # логотип PR0JECT (белый, прозрачный фон)
│   └── app.js
├── requirements.txt
├── Procfile                 # команда запуска для Railway (web, слушает $PORT)
├── .env.example
└── README.md
```
